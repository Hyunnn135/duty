# 작업 지시서: 발행·과거 달 원티드 신청 차단

- 발행일: 2026-08-20 / 티어: **T2** (사용자 행동 규칙 변경, 인증·개인정보·결제·스케줄링 핵심 규칙 아님)
- 마스터 계획 승인: **승인됨 (A안 = 차단)** — 2026-08-20

## 배경
부서원이 이미 근무표가 발행된 달 또는 지나간 달에 원티드를 신청해도 접수되어
"신청되었습니다"가 표시된다. 그 달은 이미 확정이라 효과가 없어 부서원이 오해하고,
부서장의 승인 목록에는 처리 불가한 신청이 쌓인다.

## 목표
이미 발행되었거나 지나간 달의 원티드 신청은 서버가 거부하고, 부서원 화면은 제출
전부터 그 이유("근무표 확정, 변경은 부서장에게 문의")를 한국어로 보여준다.

## 범위 — 포함
1. 서버 `POST /api/wanted`: (a) 해당 병동·연·월 근무표가 발행됨 (b) 신청 월이 KST 기준
   현재 연월보다 이전 → 403 + 한국어 안내(사유 + "부서장에게 직접 문의"), DB 저장 안 함
2. 서버 `GET /api/request-window/{년}/{월}`: 위 두 경우 is_open=false + 동일 취지 message
3. 프런트: 신청 탭 안내 문구가 새 규칙과 어긋나지 않는지 점검·보완
4. 문서: docs/USER_GUIDE.md에 새 규칙 반영 (교훈 L-5)
5. 자동 테스트 (테스트 데이터는 가명만 — 교훈 L-1)

## 범위 — 제외
- 기존에 쌓인 무효 신청 데이터 정리
- 부서장 신청 관리·승인 화면 변경
- 본인 신청 취소(DELETE) 동작 변경 (발행된 달의 pending도 취소는 계속 허용)
- 근무표 재발행·발행 취소 워크플로 신설
- 신청 기간 설정 기능 자체의 변경

## 수용 기준
1. 발행된 달에 POST /api/wanted → 403 + "발행"·"부서장" 문구 포함 한국어 메시지,
   wanted_requests에 행 추가 안 됨
2. KST 기준 지난 달에 POST /api/wanted → 발행 여부 무관 403 + 한국어 안내, 행 추가 안 됨
3. 해당 달 신청 기간이 열려 있거나 미설정이어도 기준 1·2 차단이 우선
4. 발행된 달·지난 달의 GET /api/request-window 응답은 is_open=false + 사유 message,
   부서원 신청 탭에서 해당 달 선택 시 차단 배너 표시 + "신청 제출" 버튼 비활성 (E2E 확인)
5. 발행되지 않은 현재·미래 달은 기존과 동일 동작 (기간 열림→접수, 닫힘→기존 403),
   전체 회귀 테스트 초록
6. docs/USER_GUIDE.md에 "발행된 달·지난 달은 신청 불가, 변경은 부서장 문의" 명시

## 완료 조건
수용 기준 1~6을 품질부가 구현과 분리된 컨텍스트에서 확인 + 전체 테스트·E2E 통과
(테스트 완화 없음) + 마스터 배포 승인 → PR → CI 통과 → main 병합 → 배포 확인
