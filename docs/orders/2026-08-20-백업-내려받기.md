# 작업 지시서: 관리자용 데이터 백업 내려받기 + 미백업 경고

- 발행일: 2026-08-20 / 근거 결정: D-15(B안 승인)
- 티어: **T3(중대)** — 인증·권한 + 개인정보 반출 + DB 스키마 신설이 동시 해당
- 마스터 계획 승인: **승인됨 (2026-08-20)** — ①권한 계정 1인 지정 ②전체 데이터 반출 ③단계적 경고

## 핵심 위험 (설계 근거)
`role=="master"`는 **병동마다 부여**된다(병동 개설자=그 병동 마스터). 역할만으로 권한을
판정하면 타 병동 개설자가 전 병동 간호사 실명·사번이 든 DB를 반출할 수 있다.
→ **환경변수 allowlist + role==master 동시 충족**일 때만 허용한다.

## 목표
허가된 단일 계정만 버튼 한 번으로 일관성 있는 전체 백업을 내려받을 수 있고,
마지막 백업 후 30일이 지나면 백업을 실제로 할 때까지 경고가 반복 노출된다.

## 범위 — 포함
1. `GET /api/admin/backup` — 인증 필수, 허가 계정만 200(ZIP), 그 외 403(무인증 401)
2. 일관성 있는 스냅샷: `VACUUM INTO` (폴백 `Connection.backup()`). **파일 직접 복사 금지**
   (운영 DB는 WAL 모드라 -wal 미반영/손상 위험)
3. 권한: 환경변수 `DUTY_BACKUP_OWNER`(사번/이메일, 콤마 구분) ∧ role==master.
   admin·staff 불허. **미설정이면 전원 403**(기본 개방 금지)
4. `backup_log` 테이블 신설(actor, ward, created_at, byte_size, status) +
   `GET /api/admin/backup/status` → {last_backup_at, days_since, level: ok|warn|critical}
5. 프런트: 설정 영역 "💾 백업 내려받기" 버튼 + 경고 팝업/고정 배너, 허가 계정에만 노출
   (`data-admin` 재사용 금지 — 별도 플래그)
6. 자동 테스트(권한 경계·일관성·상태 계산·노출 제어). 데이터는 가명만(교훈 L-1)
7. 문서: USER_GUIDE(백업 방법·보관 주의), DEPLOY(환경변수·복구 절차) — 교훈 L-5

## 산출물 구성 (ZIP 1개)
- `duty.db` — 복구 정본
- `tables/{테이블}.csv` — 7개 전량, **UTF-8 BOM**(엑셀 한글 깨짐 방지)
- `README.txt` — 한국어: 무엇인지 / 백업 시각(KST) / 복구 요청 방법 / 개인정보 포함, 공유 금지
- 임시 파일은 `finally`에서 반드시 삭제(개인정보 잔존 금지)

## 경고 규칙 (마스터 승인)
- 0~29일: 경고 없음, 설정에 "마지막 백업: N일 전"만 표시
- 30일↑: 로그인 후 첫 진입 시 팝업 [지금 백업하기]/[오늘은 나중에].
  "나중에"는 **KST 당일 자정까지만** 유효 → 다음 날 재노출
- 45일↑: 팝업 + **닫을 수 없는 상단 고정 배너**, 백업 성공 시에만 사라짐
- 경과일 판정은 **서버가 계산**(저장 UTC / 판정·표시 KST — 교훈 L-4)

## 범위 — 제외
복원(업로드) 기능, 자동·정기 백업, 외부 스토리지 업로드, 메일 발송,
병동별 부분 백업, ZIP 암호화, 기존 엑셀 내보내기 변경, 인프라 변경

## 수용 기준
1. 허가 계정 → 200+ZIP / 미허가 master·admin·staff → 403 / 무인증 → 401.
   거부 응답 본문에 실명·사번 미포함. `DUTY_BACKUP_OWNER` 미설정 시 전원 403
2. 백업 직전 커밋된 행이 ZIP의 duty.db와 해당 CSV **양쪽**에 존재. 백업 중·후에도
   원본 DB 읽기·쓰기가 계속 성공
3. ZIP에 duty.db 1개 + 7개 CSV + README.txt. CSV 첫 3바이트가 UTF-8 BOM,
   한글 헤더 정상. 요청 종료 후 서버에 백업 임시 파일 잔존 0
4. 성공 1회당 backup_log 행 1개(status='ok', byte_size>0). 403 요청은 행 미추가
5. KST 기준 경과 29일→ok / 30일→warn / 45일→critical / 이력 0건→critical.
   UTC로 계산하면 달라지는 경계 시각에서도 KST 결과가 나옴
6. (E2E) warn에서 팝업 표시, "오늘은 나중에" 후 같은 날 재노출 안 됨·날짜 바뀌면 재노출.
   critical에서 닫기 불가 배너 표시, 백업 성공 후 배너·팝업 소멸.
   staff·admin 로그인 시 버튼·팝업·배너·상태가 DOM에 렌더링되지 않음
7. USER_GUIDE·DEPLOY 문서 갱신, 전체 테스트·E2E 초록, 기존 테스트 완화 0,
   신규 테스트에 실명·실제 사번 없음

## 완료 조건
품질부 독립 검증(구현 역산 금지) + **검수부 3관점**(①권한·인증 우회 ②개인정보 반출·잔여
③데이터 일관성·복구 가능성) + 판별력 입증(역대조/표적 뮤테이션, 실패 로그 첨부) +
전체 테스트·E2E 통과 + 마스터 배포 승인 → PR → CI → 병합 → 배포 확인 + 교훈 대장 기록

## 관련 교훈
L-1(테스트 데이터 가명만) · L-4(저장 UTC/판정 KST) · L-5(동작 규칙 변경 시 문서 동시 갱신)

## 마스터 전결 처리 결과

  설정한다(구현 완료 후 사무국이 설정 방법 안내)
