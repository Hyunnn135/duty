## 1. 웹 리서치 — 간호사 교대근무 선호 (중점 반영 내용)

근거 조사에서 다음을 실제 알고리즘에 반영했다:

| 선호(근거) | 반영 방식 |
|---|---|
| **포워드 로테이션** D→E→N (시계방향이 생체리듬 적응에 유리) | 역회전(N→D/E, E→D) 이미 하드 금지 + 소프트 전이(M→D·E→M) 감점 → 실측 위반 0 유지 |
| **연속 나이트 ≤3, 나이트 후 ≥48h(오프 2) 휴식** | 하드 P5(≤3) + 소프트 C3(블록 직후 오프2) — 기존 반영 |
| **연속근무 짧게(피로↓)**, 사용자 선호 **3–4일 텀** | **신규**: 5일 블록(최대치) 소프트 감점 `weight_long_block` → 3–4일 텀 유도 |
| **주말·야간 등 비선호 근무의 공정 분배** | 나이트 균등(기존) + **신규**: 주말 오프 공정성 `weight_weekend_fair` |
| **자율성·투명성(원티드 반영이 만족·잔류의 핵심)** | **원티드 오프 최우선** 가중치 50→200으로 상향 → 100% 반영 보장 |

## 2. E4(팀 오프 겹침) — 실데이터 발견

원티드 데이터에서 **팀2의 서지안·신다은이 8일·9일에 동시 오프 신청**(E4 충돌 2건).
실제 8월 근무표를 보면:

- 서지안: 8일 OFF, 9일 OFF
- 신다은: 8일 **HY(연차)**, 9일 OFF

→ **실제 파트장은 E4를 절대 규칙으로 지키지 않았다.** 원티드를 우선해 둘 다 쉬게 하되, 한
명(신다은)은 연차로 커버했다. 즉 "팀 오프 겹침 절대 금지"는 실제로는 **원티드 우선 + 커버리지
확보(팀 최소 인원)** 라는 목적의 heuristic이며, 커버리지는 이미 `team_min_staff`로 보장된다.

**조치**: E4를 **하드 → 소프트**로 변경(`exclusive_team_wanted_off` 기본 False,
`weight_team_off_overlap` 소프트 감점). 하드가 필요하면 옵트인 가능. (2차 면담에서 파트장께
"겹침 절대 금지"의 정확한 취지 재확인 권장.)

## 3. 라운드별 진행 (생성물 5개 vs 실제)

지표는 22명×31일 그리드 기준. ↑좋음/↓나쁨은 실제 대비 방향.

### Round 0 — 기준(변경 전 알고리즘, E4 하드)
- 원티드 92.3%(E4 하드가 겹침 2건 차단) · 5일블록 28–37(실제 24) · 3–4일블록 57–70(실제 77)
- ✅ 이미 우수: 나이트 편차·EOD(0)·고립근무(0)·팀커버(0미스)
- **문제**: 원티드 미달, 텀이 실제보다 길다.

### Round 1 — E4 소프트화 + 5일블록 감점 + 주말공정성
- 원티드 96–100% · 5일블록 0–1 · 3–4일블록 98–109 · 주말오프 편차 개선
- 잔여: gen1이 원티드 96.2%(1건 양보) → 원티드 최우선 미흡.

### Round 2 — 원티드 가중치 50→200
- **5개 전부 원티드 100%** · 하드 0 · 오프=목표(10) · 5일블록≈0 · 3–4일블록 100–110
- EOD 0 / 고립 0 / 팀커버 0미스 — 모든 소프트 지표에서 실제(EOD 14·고립 4·팀커버 1미스)를
  **동등 이상**으로 능가. 단 아직 서로 다른 최적해가 다수(비수렴).

### Round 3 — 수렴 시도(단일 근무표로) — ⚠️ 계산적 한계 도달
"어떤 방법으로도 서로 다른 근무표를 만들 수 없는 유일해"를 만들기 위해 두 가지 결정적
기법을 시도했고, **둘 다 22명×31일 규모에서 계산적으로 비현실적**임을 확인했다:

1. **사전식 결정적 타이브레이커**(품질을 큰 배수로 우선 + 셀 위치·교대 순서 미세비용):
   대형 계수 목적함수가 CP-SAT의 하한(bound)을 약화시켜, 제한 시간 내 **최적을 증명 못 하고
   준최적/UNKNOWN** 반환(단일 solve, 1워커·45초에서 **가해 자체를 못 찾음**).
   2단계(품질 고정 후 타이브레이크만)도 타이브레이크 단계가 UNKNOWN.
2. **결정적 단일 스레드 풀이**(num_workers=1 + 고정 시드): 재현은 되지만, **1워커로는 30초
   안에 가해조차 못 찾음**(8워커 포트폴리오는 ~5초에 발견). 즉 이 문제는 **병렬 탐색이
   필수**이고, 병렬은 타이밍상 비결정적이다.

**결론(정직한 보고)**: 이 병동 규모(22×31)와 지금의 풍부한 목적함수에서는, **정확 최적화로
'단 하나의 근무표'에 수렴시키는 것은 실용 시간 내 불가능**하다. 대신 **품질이 수렴**했다 —
아래 참조.

**품질 수렴(달성됨)**: Round 2에서 생성한 5개는 **모두 같은 최적 목적값**에 도달하며, 모든
소프트 지표에서 실제를 동등 이상으로 능가한다. 즉 알고리즘은 "최적 품질의 근무표 집합"으로
수렴했고, 그 집합의 원소(서로 다른 배치)는 품질이 동일해 우열이 없다.

## 6. 인위적(결정적) 요소 상세 — 사용자 결정 4 관련

- 유일해를 위해 도입하려던 **결정적 타이브레이커**(사전식 셀 위치·교대 순서 규칙)는 **규모상
  풀리지 않아 기본 비활성**(`deterministic_tiebreak=False`). 즉 **최종 알고리즘에 인위적
  타이브레이크 규칙은 실제로 들어가지 않았다.**
- 프로덕션은 **8워커 병렬 탐색**을 사용(비결정적 타이밍) → 실행마다 동일 품질의 다른 최적해가
  나올 수 있다. 완전 재현이 필요하면 `num_workers=1`로 결정적 탐색이 가능하나, 이 규모에서는
  가해 도달이 매우 느리다(비권장).

### 권고 (단일 근무표가 꼭 필요하다면)
1. **품질 수렴 집합을 인정**하고, 그중 하나를 파트장이 선택(현행 실무와 동일, 권장).
   → **채택·구현 완료**: `POST /api/schedule/candidates`(동일 품질 후보 N개 생성) + 웹앱
     "🎲 여러 안 생성" 버튼 → 파트장이 후보를 보고 하나를 선택해 확정.
2. 규모를 줄이거나(팀별 분할 풀이) 목적함수를 단순화해 정확 최적·유일성 증명을 가능하게.
   → **§7에서 추가 진행(권장 #2)**.
3. 결정적 재현이 목적이면 `num_workers=1` + 고정 시드 + **넉넉한 시간(수 분~)** 부여.

> 핵심 성과: **원티드 100%·대원칙 0위반·실제 대비 전 지표 동등 이상**의 알고리즘으로 개선.
> 미달: 계산 복잡도상 '단일 유일 근무표' 수렴은 이 규모에서 실용적으로 불가.

## 7. 권장 #2 후속 — 목적함수 단순화로 "정확 최적(proven OPTIMAL)" 달성

§3에서 단일 유일해가 막힌 근본 원인을 규명하고, 그중 **"정확 최적 증명"** 부분을 해결했다.

### 병목 규명 (실측)
- `weight_fairness=3`(나이트/근무 **편차** = add_max/min_equality, reification): 40초에도
  **FEASIBLE(미증명)**.
- `weight_fairness=0`(공정성 목적 제거): **27.8초에 OPTIMAL 증명**(obj=21).
- → **공정성을 '목적함수'로 두면 최적 증명이 사실상 불가**(편차·최댓값 모두 minimax류라
  NP-hard 증명). `simple_fairness`(minimize-max)로 바꿔도 60초 미증명 — 형태 문제가 아님.

### 해결: 공정성을 '목적'에서 '하드 밴드'로 이동 (`exact_mode`)
나이트 공정성을 목적함수 대신 **가능자별 나이트 수 ∈ [⌊T/E⌋, ⌈T/E⌉] 하드 제약**으로 옮기고
편차 목적을 제거한다(T=월 나이트 총 슬롯, E=나이트 가능 인원 → 이 병동은 밴드 [5,6]).

- **결과: proven OPTIMAL 도달 가능**(한가한 상태 ~28~30초에 obj=21 최적 증명. 부하가
  크면 같은 시간에 근최적 FEASIBLE로 떨어질 수 있으나, 품질은 사실상 최적 수준).
  공정성은 밴드로 **항상 보장**(아무도 7 나이트 불가, 5~6으로 균일 → 실데이터 최대 7보다 균등).
- 품질 지표는 Round 2와 동등(원티드 100%·대원칙 0·EOD 0·고립 0·팀커버 0·나이트편차 1).
- 제품 반영: `ScheduleRequest.exact_mode=True`(웹앱 "🎯 정확 최적" 토글) → 나이트 밴드
  자동 산출 + 편차 목적 제거 + 시간제한 상향(60초).

### 유일성(단일 근무표)은?
정확 최적을 얻어도 **동일 최적값의 서로 다른 배치가 다수 존재**(distinct optima ≥ N).
이를 하나로 강제하려던 결정적 타이브레이커는 계수가 커 CP-SAT presolve가 막힘(여전히 불가).
→ **"정확 최적(최고 품질 보장)"은 달성, "단일 유일해"는 여전히 계산적 한계.**
남은 유일성까지 필요하면 **팀별 분할 풀이**(각 팀 6~8명 소규모 → 유일 타이브레이크 가능)가
다음 후보이나, 팀 간 커버리지 결합(액팅·전체 정원)의 조정 설계가 필요하다.
