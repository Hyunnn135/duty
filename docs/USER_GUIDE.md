# 사용 설명서 — 간호사 근무표 자동 생성

이 문서는 **파트장(관리자)**, **부서원**, **운영자** 각 역할이 웹앱을 실제로 쓰는 방법을
단계별로 설명합니다. 처음 쓰시는 분도 순서대로 따라 하면 됩니다.

---

## 0. 로그인 · 역할

앱에 접속하면 로그인 창이 뜹니다. 처음이면 **"회원가입"** 을 누릅니다.

- 회원가입 시 **사번**(숫자/영문 3~20자)이 **로그인 아이디**입니다. 이메일은 선택
  사항이며 승인·반려 등 알림 수신용으로만 쓰입니다.
- 예전에 이메일로 가입한 분은 그대로 이메일로 로그인할 수 있고, 로그인 후 우측
  상단 **"사번 등록하기 →"** 로 사번을 등록하면 다음부터 사번으로 로그인됩니다
  (명단 계정 연결·원티드 신청도 사번 기준으로 자동 이관).

- **병동을 처음 개설하는 사람**(보통 파트장): "병동"란에 병동명(예: `61`)을 입력해
  가입하면 자동으로 그 병동의 **운영자**가 되고, **초대 코드 8자리**가 발급됩니다
  (설정 탭 → 🔑 부서원 초대 코드에서 확인·복사·재발급).
- **부서원**: 부서장에게 받은 **초대 코드**를 입력해 가입합니다(병동 자동 설정).
  코드 없이는 이미 개설된 병동에 가입할 수 없습니다 — 외부인 접근 차단용이니
  코드는 병동 밖으로 공유하지 마세요. 유출이 의심되면 재발급하면 됩니다.
- 역할 변경(파트장 승격 등)은 운영자가 하며, **즉시 반영**됩니다.

| 역할 | 할 수 있는 일 | 보이는 탭 |
|------|--------------|-----------|
| **운영자** | 모든 것 + 역할 관리 + 피드백 수신함 | 설정·근무표·신청관리·통계·수신함 |
| **파트장(관리자)** | 명단·근무표 생성·발행·원티드 승인 | 설정·근무표·신청관리·통계 |
| **부서원** | 원티드 신청·내 근무/통계 조회 | 근무표·원티드 신청·내 통계 |

## 1. 파트장(관리자) — 근무표 만들기

### 1-A. 명단 입력 (한 번만, 이후 수정)

**설정 탭 → 👥 간호사 명단**

1. 명단은 **A/B/C 팀 섹션**으로 나뉘어 보입니다. **위→아래 = 경력순**(위가 고참)이며,
   이름 왼쪽 ⠿를 드래그하거나 ▲▼ 버튼으로 순서·팀을 바꿉니다(순위 숫자 입력 없음).
   - **나이트**: 야간 근무 가능 여부(임신·산후 등은 체크 해제)
   - **트레이닝**: 입사 첫 달 교육 대상이면 체크(정원에서 빠지고 교육자와 같은 근무)
   - **교육자**: 트레이닝인 경우 따라다닐 선배 선택
   - **단독근무**: 트레이닝 직후 신규가 팀 듀티를 혼자 감당하지 못하는 경우 설정
     (모두 가능 / 나이트만 / 데이·이브만 / 모두 불가). "불가"로 표시된 교대에서는
     그 신규가 팀의 유일한 근무자가 되지 않도록, **단독 가능한 팀원이 반드시 같은
     듀티에 함께 배정**됩니다(하드 규칙). 각 팀에는 매일 D/E/N마다 단독 가능 인원이
     최소 1명씩 보장됩니다.
2. **"명단 저장"** 을 누르면 서버에 저장됩니다. 다음에 접속해도 유지됩니다.

### 1-B. 편성 조건 확인

**설정 탭 → 📅 편성 기간 & 인원 기준**

- **연도·월**: 만들 달
- **Day/Evening/Night 최소·적정 인원**: 기본값 4/4/4
- **공휴일**: 대체공휴일 포함 **자동 적용**됩니다(화면에 이번 달 공휴일이 표시됨).
  임시공휴일이 지정된 해에는 관리자에게 공휴일 표 갱신을 요청하세요.
- 월 오프 수는 (토+일+공휴일) 수에 맞춰 자동 계산됩니다.

### 1-C. 운영 모드 (핵심)

**설정 탭 → 🎯 운영 모드** — 기본으로 켜져 있습니다(권장).

- 켜면 매일 인원이 **D4·E4·N4·M1(액팅 있는 날)** 또는 **D5·E5·N4(액팅 없는 날)**
  중 하나로 **정확히** 맞춰집니다(초과·미달 불가).
- **액팅(미드) 근무 일수**: 한 달에 액팅을 넣을 날 수(기본 8).
  - 액팅을 늘리면 오프 12개인 인원이 늘고, 줄이면 오프 11개인 인원이 늘어납니다
    (액팅 1일 = 오프 12명 1명 증가). 병동 상황에 맞게 조절하세요.
- 나이트 균등·오프 11~12 균등·원티드 100% 우선이 자동으로 함께 적용됩니다.

### 1-D. 원티드 · 사전배정 · 전월 이월 (선택)

**설정 탭 → 📝 원티드 · 사전배정 · 전월 이월**

- **원티드 신청**: 한 줄에 하나. `이름, 시작일, 종료일, 종류(O/D/E/N)`
  - 하루만이면 종료일 생략 가능: `김민지, 3, O` (3일 오프)
  - 종류 생략 시 오프(O)로 간주: `김민지, 3, 5` (3~5일 오프)
  - 오프(O)는 최우선 반영, 같은 팀 오프 겹침은 가급적 피하도록 반영됩니다(불가피하면 허용).
- **사전 확정 휴무(연차 등)**: `이름, 날짜, 코드(HY/공가/병가/Edu/경조/PH/AH)`
- **전월 말일 이월**: **자동** — 발행된 전월 근무표의 마지막 7일이 자동 반영됩니다
  (발행된 전월 표가 없으면 이월 없이 생성).

> 부서원이 웹으로 신청한 원티드는 "신청관리"에서 승인하면 자동 반영됩니다(2-B). 위 칸은
> 파트장이 직접 넣을 때 씁니다.

### 1-E. 생성

**설정 탭 하단 → "근무표 생성"**

- 운영 모드에서는 최고 품질 계산을 위해 **약 1~2분** 걸립니다. 창을 닫지 마세요.
- 완료되면 자동으로 **근무표 탭**으로 넘어갑니다.
- **"여러 안 생성(3)"**: 같은 품질의 서로 다른 후보를 3개 만들어 고를 수 있습니다.

### 1-F. 검토 · 수정 · 발행

**근무표 탭**

- 달력형 표에서 요일·주말 음영·팀 구분·교대별 합계(Σ)·개인 카운트를 확인합니다.
- 셀을 직접 고치면 **대원칙 위반을 자동 검사**해 경고합니다. 위반 시 **"대안 3안 보기"** 로
  최소 수정안을 받을 수 있습니다.
- CSV·엑셀·PNG로 내보낼 수 있습니다.
- **"📢 발행"** 을 누르면 병동 구성원 모두가 자기 근무를 조회할 수 있습니다.

---

## 2. 파트장 — 원티드 신청 관리

**신청관리 탭**

### 2-A. 신청 기간 설정
- 부서원이 원티드를 낼 수 있는 **여는 시각·닫는 시각**을 정하고 **"기간 저장"**.
- 기간이 지나면 부서원 화면에 만료 문구가 뜨고 신청이 막힙니다.
- **근무표를 발행한 달과 이미 지나간 달은 신청 기간과 무관하게 부서원 신청이 자동으로
  막힙니다** (기간을 열어 두어도 마찬가지). 처리 불가한 신청이 승인 목록에 쌓이지
  않도록 하기 위함입니다.

### 2-B. 신청 승인/반려
- 부서원이 낸 원티드 목록이 보입니다. **승인**하면 다음 생성 때 반영, **반려**도 가능.
- (가입 시 이메일을 등록한 경우) 승인·반려 결과가 신청자에게 메일로 전달됩니다.
  사번만으로 가입해 이메일이 없으면 메일 알림은 가지 않습니다.

---

## 3. 부서원 — 원티드 신청 · 내 근무 조회

### 3-A. 계정 연결 (처음 한 번)
로그인 후 "명단 미연결"이 보이면, **파트장에게 내 계정을 명단의 내 이름에 연결해 달라고
요청**하세요(파트장이 설정 탭 명단의 "계정" 칸에서 연결). 연결되면 "내 근무/내 통계"가
내 이름 기준으로 동작합니다.

### 3-B. 원티드 신청
**원티드 신청 탭** — 신청 기간 안에서 원하는 오프/근무 날짜를 제출합니다.

> **이미 근무표가 발행된 달과 지난 달은 신청할 수 없습니다.** 그 달은 이미 확정되어
> 신청을 받아도 반영되지 않기 때문이며, 신청 기간이 열려 있어도 막힙니다. 신청 탭에서
> 그런 달을 고르면 사유 안내가 뜨고 "신청 제출" 버튼이 잠깁니다.
> 그 달에 변경이 필요하면 **부서장에게 직접 문의**하세요.

### 3-C. 내 근무 · 통계
- **근무표 탭**: "내 근무만" 체크로 내 근무만 볼 수 있습니다.
- **내 통계 탭**: 내 D/E/N/오프 집계·나이트 분포를 봅니다(본인 것만 보임).

### 3-D. 피드백
근무표에 대한 의견을 보내면 **운영자 수신함**으로 전달됩니다.

## 4. 운영자 전용

- **역할 관리**: 부서원을 파트장으로 올리거나 내릴 수 있습니다.
- **📨 수신함**: 부서원 피드백을 모아 봅니다.

### 4-A. 💾 데이터 백업 내려받기

**⚙️ 설정** 탭의 **💾 데이터 백업** 카드에서 **[💾 백업 내려받기]** 를 누르면
명단·근무표·원티드 신청 등 **모든 데이터**가 ZIP 파일 하나로 내려받아집니다(몇 초 소요).

> 이 버튼은 **권한을 등록한 계정**에만 보입니다. 운영자(마스터)라도 등록하지 않았으면
> 보이지 않고, 주소를 직접 입력해도 서버가 거부합니다.

**백업 버튼을 쓰려면 (처음 한 번)**

1. 배포 담당자에게 **백업 권한 코드**를 받습니다(담당자가 서버에 넣어 둔 무작위 문자열입니다).
2. **⚙️ 설정** 탭의 **🔐 백업 권한 등록** 카드에 그 코드를 입력하고 **[등록]** 을 누릅니다.
3. 등록 카드가 사라지고 그 자리에 **💾 데이터 백업** 카드가 나타나면 끝입니다.

> - 코드는 **한 번만** 쓰면 됩니다. 앱에 저장되지 않으니 따로 적어 두지 말고 지우세요.
> - 코드를 **여러 번 잘못 입력하면 15분간 잠깁니다.** 맞는 코드인지 담당자에게 확인하세요.
>   (잠기는 것은 **그 계정**뿐입니다. 다른 담당자는 그대로 등록할 수 있습니다.)
> - **서버 데이터가 초기화되면 권한도 함께 사라집니다.** 그때는 담당자에게 새 코드를 받아
>   다시 등록하면 됩니다(고장이 아니라, 아무나 권한을 가로채지 못하게 하는 장치입니다).

**담당자가 바뀌거나, 코드가 샜을 때 — 🔓 백업 권한 회수**

백업 권한은 **계정에 붙어 있어 그냥 두면 사라지지 않습니다.** 담당자가 바뀌거나 퇴사하거나
코드가 샜다고 판단되면, 새 사람이 등록하기 **전에 먼저 회수**하세요. 그냥 새로 등록만 하면
**이전 담당자의 권한은 그대로 남습니다.**

1. 배포 담당자에게 **권한 코드를 새로 바꿔 달라고 요청**합니다(샌 코드를 무력화합니다).
2. **⚙️ 설정 → 💾 데이터 백업** 카드 아래의 **🔓 백업 권한 회수** 를 펼칩니다.
3. **새 코드를 입력하고 [권한 회수]** 를 누릅니다. 확인 창이 한 번 더 뜹니다.
4. 화면에 **회수된 건수**가 나옵니다. **1보다 크면 나 말고도 백업 권한을 가진 계정이
   있었다는 뜻**이니 운영 담당자에게 알리세요.
5. 새 담당자가 로그인해 **🔐 백업 권한 등록** 카드에 새 코드를 넣으면 끝입니다.

> - 회수하면 **본인을 포함해 권한을 가진 모든 계정**의 백업 권한이 한 번에 꺼집니다.
>   "누가 등록해 뒀는지 모르는 상태"를 한 번에 정리하기 위한 것입니다.
> - **데이터는 지워지지 않습니다.** 지워지는 것은 권한뿐이고, 코드로 언제든 다시 등록합니다.
> - 회수에도 **권한 코드가 필요합니다.** 코드를 모르면 배포 담당자에게 요청하세요.

**ZIP 안에 들어 있는 것**

| 파일 | 내용 |
|------|------|
| `duty.db` | **복구에 쓰는 정본**입니다. 열거나 이름을 바꾸지 말고 그대로 두세요. |
| `tables/*.csv` | 표(엑셀)로 열어 볼 수 있는 사본입니다(한글 안 깨짐). 계정 목록·명단·근무표·원티드 신청·신청 기간·**수신함 피드백 원문**·초대 코드 표, 7개 파일입니다. |
| `README.txt` | 백업 시각(한국 시간)과 보관·복구 안내입니다. |

CSV를 볼 때 알아둘 점:

- 비밀번호와 초대 코드 자리에는 값 대신 **`(생략)`** 이 적혀 있습니다. 새어 나갔을 때
  그대로 침입에 쓰이는 값이라 일부러 가린 것이며, 복구는 `duty.db`로 하므로 지장이 없습니다.
- 빈칸은 "값이 없음"과 "빈 글자"를 구분하지 않습니다.
- 명단·근무표 CSV의 `data` 칸에는 값 대신 **`(JSON — duty.db 참조)`** 라고만 적혀 있습니다.
  프로그램이 쓰는 형식이라 사람이 읽을 수 없고, 그대로 실으면 파일이 지나치게 커집니다.
  내용을 눈으로 확인하실 때는 앱 화면이나 엑셀 내보내기를 쓰세요.

## 6. 자주 묻는 질문

**Q. 왜 어떤 사람은 오프가 11개, 어떤 사람은 12개인가요?**
22명·31일·정확 인원 규칙에서는 전원 오프 11이 산술적으로 불가능합니다. 가장 공정한
분포가 11개 일부 + 12개 일부이며, 12개인 사람은 하루 더 쉬는 것이라 손해가 아닙니다.
액팅 일수를 바꾸면 이 비율이 달라집니다(운영 모드 참고).

**Q. 첫 접속 때 8~10초 멈춰요.**
비용 절감을 위해 안 쓸 때 서버를 꺼두기 때문입니다(scale-to-zero). 첫 요청 시 켜지는
시간이며, 이후엔 빠릅니다. 항상 즉시 응답이 필요하면 관리자에게 문의하세요.

**Q. 이미 나온(발행된) 근무표의 달에 원티드를 넣고 싶어요.**
그 달은 확정되어 신청을 받아도 반영할 수 없으므로 신청이 막힙니다. 지난 달도 같습니다.
변경이 필요하면 **부서장에게 직접 문의**하세요.

**Q. 백업 버튼이 안 보여요.**
백업은 **권한을 등록한 계정**만 쓸 수 있습니다. 개인정보가 통째로 들어 있는 파일이라
운영자(마스터)라도 등록 전에는 보이지 않습니다. **⚙️ 설정 → 🔐 백업 권한 등록** 카드에
배포 담당자에게 받은 코드를 넣으세요(4-A 참고). 그 카드도 안 보인다면 마스터 계정이
아니거나, 화면이 서버 상태를 아직 못 받은 것입니다 — **[🔄 다시 시도]** 가 보이면 눌러 보세요.

**Q. 백업 담당자가 바뀌었습니다. 새로 등록하면 되나요?**
**등록만 하면 안 됩니다.** 권한은 계정에 붙어 있어서, 새로 등록하면 새 계정에 권한이
하나 더 생길 뿐 **이전 담당자의 권한은 그대로 남습니다.** 4-A의 **🔓 백업 권한 회수**로
먼저 전부 회수한 뒤 새 담당자가 등록하세요. 퇴사·코드 유출 때도 같습니다.

**Q. 컴퓨터를 바꿔도 되나요?**
됩니다. 모든 데이터는 서버(클라우드)에 있어, 어느 기기서든 **같은 계정으로 로그인**하면
이어서 쓸 수 있습니다.

**Q. 근무표가 실제 작년/지난달과 똑같이 나오지 않아요.**
같은 조건에서도 품질이 동일한 다른 배치가 여러 개 존재합니다("여러 안 생성"으로 비교
가능). 대원칙과 원티드를 모두 지키는 한, 여러 정답 중 하나가 나옵니다.
