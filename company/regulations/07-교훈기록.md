# 제7장 — 교훈·기록 규정

> 원칙: **"기능의 절반은 교훈"** — 1인 회사의 조직 기억은 문서가 대체한다.
> 같은 실수를 두 번 하면 그것은 에이전트의 실패가 아니라 기록 체계의 실패다.

## 1. 교훈 대장 (`company/ledger/lessons.md`)

1. 다음 사건은 반드시 교훈 대장에 기록한다:
   - T3 작업에서 발견된 모든 결함과 해결
   - 검수부·상호감시로 잡힌 규정 위반
   - 배포 후 발견된 버그(테스트가 못 잡은 것 — 왜 못 잡았는지 포함)
   - 마스터가 지적한 보고·소통 문제
   - 반복될 수 있는 실수의 패턴
2. 기록 양식:
```
## L-<번호> <제목> (날짜)
- 무슨 일: 1~2문장
- 원인: 근본 원인 (표면 증상 말고)
- 조치: 무엇을 고쳤나
- 재발 방지 규칙: 다음 작업자가 따라야 할 한 문장
```
3. **모든 부서는 작업 착수 전에 교훈 대장의 재발 방지 규칙을 훑는 것을
   전제로 한다.** 사무국은 지시서에 관련 교훈 번호를 링크한다.

## 2. 결정 기록부 (`company/ledger/decisions.md`)

1. 마스터의 모든 결정(승인·반려·위임·정책)을 날짜와 함께 한 줄씩 기록한다.
2. 목적: ①같은 안건을 다시 묻지 않기 ②"왜 이렇게 되어 있지?"에 답하기
   ③위임 범위의 증거.
3. 양식: `D-<번호> (날짜) <결정 내용 한 문장> — 배경 링크`

## 3. 문서 유지 의무

1. 규정·역할 파일·사용 설명서는 실제 동작과 어긋나는 순간 고친다. 문서와
   현실이 다르면 그 자체를 결함으로 취급한다(검수부 점검 대상).
2. 사용자 대상 문서(듀티원 사용 설명서 등)는 고객지원부 소관, 회사 내부 문서는
   사무국 소관.
