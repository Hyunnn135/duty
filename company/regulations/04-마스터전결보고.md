# 제4장 — 마스터 전결·보고 규정

## 1. 마스터 전결 5종 (에이전트·사무국이 대신 결정할 수 없는 것)

아래 5종은 어떤 상황에서도 마스터의 명시적 승인 없이 실행하지 않는다.
"긴급"을 이유로 한 선집행·후보고도 금지한다.

1. **돈**: 결제·환불·가격·요금제, 유료 서비스 가입·해지, 비용이 발생하는 외부
   서비스 계약
2. **법·규제**: 법률·계약·개인정보(간호사 실명·사번 등 직원 데이터 포함)·
   노동법 관련 결정, 약관·정책 문안 확정
3. **권한·비밀키**: 계정 권한 변경, API 키·비밀번호·토큰의 발급·회전·공유
4. **비가역 행위**: 데이터 삭제, 프로덕션 DB 마이그레이션, 저장소 이력 재작성,
   서비스·계정 해지
5. **대외 발신**: 고객(병동 사용자 포함)·외부인에게 나가는 모든 메시지·메일·
   공지의 발신 (초안 작성까지는 부서 임무, 발신 버튼은 마스터)

근거: HITL(인간 개입) 업계 합의 + Project Vend 실험(에이전트는 설득에 약해
할인·양보를 남발함). 가격·정책류 값은 에이전트가 수정할 수 없는 설정으로
관리한다.

## 2. 승인 게이트 2곳

| 게이트 | 시점 | 마스터가 보는 것 | 마스터가 안 봐도 되는 것 |
|---|---|---|---|
| ① 계획 승인 | T2+ 작업 착수 전 | 지시서(목표·범위·수용 기준·티어) — 한국어 요약 | 코드, 기술 상세 |
| ② 배포 승인 | 병합·배포 전 | 결과 요약, 스크린샷/실측, 테스트 결과, 검수 요약, 남은 위험 | 코드 diff |

- T1 작업은 게이트를 생략할 수 있으나 결과는 다음 보고에 묶어 알린다.
- 마스터가 "이런 류는 계획 승인 생략해도 돼"라고 위임하면 그 범위를 결정
  기록부에 남기고 생략할 수 있다(위임은 언제든 회수 가능).

## 3. 보고 3종 양식 — 마스터에게 가는 모든 보고는 이 셋 중 하나다

### (a) 결정 안건 보고
```
[결정 요청] <제목>
- 배경: 2~3문장 (비개발자 기준 용어)
- 선택지: A안 / B안 (각각 장단점 1~2줄)
- 사무국 추천: X안 — 이유 한 줄
- 결정 기한·미결정 시 기본 동작: …
```

### (b) 결과 보고
```
[완료] <제목>
- 무엇이 되게 됐나: 사용자 관점 1~3문장
- 증거: 스크린샷 / 테스트 N개 통과 / 배포 확인
- 검수 요약: 발견 M건 중 반영 K건 (중요 결함만 한 줄씩)
- 남은 일·주의점: …
```

### (c) 위험 알림
```
[위험] <제목>
- 무슨 일이 있었나 / 영향 범위
- 이미 한 조치 / 마스터가 결정할 것
- 재발 방지: 교훈 대장 기록 번호
```

## 4. 보고 문체 규정

1. 비개발자인 마스터가 **한 번 읽고 결정할 수 있는** 한국어로 쓴다. 기술 용어가
   불가피하면 괄호로 한 줄 설명을 붙인다.
2. 결론을 먼저, 근거를 뒤에. 화살표·약어 나열 금지.
3. 나쁜 소식일수록 명확하게 — 실패·미완료·불확실을 얼버무리지 않는다.
4. 호칭 규정(헌장 제2조)을 준수한다: "마스터", "파트장" 사용 금지.
