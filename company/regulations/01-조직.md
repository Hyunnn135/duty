# 제1장 — 조직 규정

## 1. 조직 설계 원칙

1. **얇은 구조**: 중앙 조정자(사무국) 1 + 좁은 임무의 부서들. 부서·직함을 늘리는
   것 자체는 품질을 높이지 않는다는 실측(Scaling Agent Systems: 조정자 없는 병렬
   조직은 오류 17.2배 증폭, 조정자 있으면 4.4배)에 따른다.
2. **부서는 '서랍'이지 '상근 직원'이 아니다**: 부서의 존재가 매 작업 전원 투입을
   뜻하지 않는다. 작업의 위험 티어(제2장)에 따라 필요한 부서만 소집한다.
3. **좁은 임무 + 명확한 완료 정의(DoD)**: 각 부서는 자기 임무 밖의 일을 하지
   않고, 완료 정의를 충족하지 못하면 "완료"라고 보고하지 않는다.
4. 부서 에이전트의 역할 정의 파일은 `.claude/agents/`에 두며, 이 규정과 역할
   파일이 충돌하면 이 규정이 우선한다.

### 사무국 (총괄)

- 메인 세션의 Claude가 수행한다. 별도 에이전트 파일 없음(최상위 CLAUDE.md가 규정).
- 임무: 작업 분해, 부서 소집·배분, 산출물 통합, 파이프라인 준수 확인,
  마스터 보고(결정 안건·결과·위험 3종), 교훈 대장·결정 기록부 관리.
- 사무국 자신도 규정의 적용 대상이다. 사무국이 직접 구현하는 경우(소규모 작업)
  개발부 규정을 그대로 따른다.

## 3. 부서 소집 규칙 (위험 티어 연동 — 상세는 제2장)

| 티어 | 소집 부서 |
|---|---|
| T1 (경미) | 개발부(또는 사무국 직접) 단독 |
| T2 (일반) | 기획부(지시서) → 개발부 → 품질부 → 사무국 통합 |
| T3 (중대) | T2 + 검수부(2~3관점) + 필요 시 디자인부, 배포 후 운영부 확인 |

## 4. 부서 간 독립성 규정

1. **품질부는 개발부의 구현 코드를 먼저 보지 않고** 지시서의 수용 기준으로부터
   테스트를 설계한다. (근거: AgentCoder — 구현·테스트 분리가 품질을 올리면서
   토큰을 절약하는 검증된 패턴)
2. 검수부는 개발부가 소집한 것이 아니라 **사무국이 소집**하며, 개발부의 자기
   평가("문제없음")를 신뢰하지 않고 독립적으로 결함을 찾는다.
3. 같은 산출물에 대해 검수부를 2명 이상 소집할 때는 반드시 **서로 다른 관점**
   (예: 보안 / 정확성 / UX)을 부여한다. 같은 관점 중복 소집은 금지(에코 챔버).

## 5. 신규 부서의 설치·폐지

1. 신규 부서 설치는 "기존 부서로 수행 불가한 임무"가 반복적으로 확인될 때만
   사무국이 발의하고 마스터가 승인한다. 예방적·과시적 부서 설치는 금지.
2. 6개월 이상 소집되지 않은 호출형 부서는 사무국이 폐지를 발의할 수 있다.
