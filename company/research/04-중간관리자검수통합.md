## 3. 상충 검증

**상충 1: "다수 샘플링이 성능을 올린다"(More Agents, 학술 #8) vs "호출 수 증가는 비단조 — 오르다 떨어진다"(학술 #9)**
판정: 모순이 아니라 적용 조건이 다르다. 다수 초안 생성→선택은 **자동 채점기(테스트)가 승자를 고를 수 있을 때만** 유효하고, 채점기 없이 다수결·LLM 판정에 맡기면 어려운 문제에서 다수가 오답으로 수렴해 오히려 악화된다(#9). 실무 규칙: "테스트로 선별 가능한 작업 → 다중 초안 허용, 그 외 → 단일 시도 + 실행 피드백". Agentless(#12)의 '다중 패치 생성 후 테스트 선별'이 정확히 이 안전 조건 안의 사용법이다.

**상충 2: "멀티에이전트가 단일 Opus 대비 90.2% 우위"(사례 1-1, Anthropic 리서치 시스템) vs "단일 에이전트/단순 파이프라인이 에이전트 군단을 이긴다"(학술 #10, #12, MAGIS 추월 사례)**
판정: 과업 유형이 가른다. Anthropic의 90.2%는 **분해 가능한 병렬 탐색 과업(리서치)**에서의 결과로, Scaling 논문의 "분해 가능 과업 +80.8%"와 정합한다. 반면 코드베이스 수정은 **순차 의존 과업**이라 병렬 에이전트가 -70%까지 악화되며 Agentless류 단순 파이프라인이 이긴다. 즉 "조사·설계 단계 = 병렬 서브에이전트 허용, 구현 단계 = 단일 세션(또는 독립 모듈만 worktree 병렬)"로 단계별로 다르게 운영하면 두 결과 모두와 부합한다. 사례 보고서 자체도 "선별 적용"으로 결론지어 실질적 충돌은 없다.

**상충 3: "AI 리뷰어 계층을 두라"(사례 ④, Cora Assess 다중 리뷰) vs "LLM 리뷰 승인은 러버스탬프/에코 챔버"(학술 #13, 가드레일 2-2)**
판정: 리뷰어의 **역할 정의**가 가른다. LLM 리뷰어에게 '승인 권한'을 주면 자기선호·습관화로 도장찍기가 되지만, '결함 탐색 + 우선순위 트리아지 보고서 생성'만 맡기고 승인 권한은 실행 게이트(테스트)와 인간에게 두면 유효하다. 통합 결론: **AI 리뷰어 = 조언자(결함 리스트 생산), 테스트 = 게이트, 인간 = 전결** — 세 보고서 권고를 모두 만족하는 유일한 배치다. 이는 사용자가 계획한 "중간관리자 승인" 구조에 대한 직접 수정 권고이기도 하다: 중간관리자 에이전트의 "승인"을 머지 조건으로 삼지 말 것.

**경미한 불일치**: 오류 증폭 수치(17.2배/4.4배)의 출처 귀속이 두 보고서에서 다름(§1 표 #2 참조) — 수치는 일치하므로 결론 영향 없음, 출처만 교정 필요.

## 4. 최종 통합 목록 (중복 제거·관련성 필터 적용)

### A. 조직 구조
1. 직함 많은 가상 회사 조직도는 버리고 **오케스트레이터(중간관리자) 1 + 좁은 임무의 워커 소수** 얇은 구조로 시작한다 — 역할 수 증가 자체는 품질 근거가 없다. [학술][사례][가드레일]
2. 조직도는 파일로 구현한다: CLAUDE.md(회사 규정집) + `.claude/agents/` 역할 파일 3~5개(플래너/빌더/테스터/리뷰어), 공개 저장소에서 필요한 것만 발췌. [사례]
3. 병렬화는 **서로 독립적인 작업에만** git worktree 3~5개로 제한하고, 순차 의존 작업(같은 모듈 연쇄 수정)은 단일 세션으로 처리한다. [학술][사례]
4. 각 에이전트에 완료 정의(DoD)·종료 조건·반복 횟수 상한을 명문화한다 — 실패의 40%+는 명세 불량에서 온다. [학술][가드레일]
5. 작업 단위는 수용 기준을 적은 GitHub Issue(티켓)로 발행한다 — 비개발 오너의 지시서이자 검수 기준. [사례]

### B. 검증/리뷰 방식
6. **머지 게이트는 LLM 리뷰가 아니라 실행 게이트**: CI 테스트 통과·스키마 diff·마이그레이션 dry-run이 통과 조건이다. [학술][사례][가드레일]
7. 간호사 스케줄링 핵심 제약(근무 규칙·노동법)은 **골든/속성 기반 테스트로 굳혀 LLM 판정 대상에서 아예 제외**하고, 테스트 작성자는 구현자와 컨텍스트를 분리한다(AgentCoder 방식). [학술][가드레일]
8. 중간관리자(리뷰) 에이전트는 승인자가 아니라 **결함 탐색+트리아지 보고자**로 정의한다: "거부해야 할 이유 N개를 먼저 찾아라" 적대적 프레이밍 + 루브릭 채점 + 테스트 결과 첨부 의무. [학술][사례][가드레일]
9. 자동 채점(테스트)이 가능한 작업에 한해 다중 초안 생성 후 테스트로 선별하는 방식을 쓴다 — 채점기 없는 다수결·토론은 금지. [학술]
10. 위험 티어링: 문서·UI 문구는 리뷰 생략/저가 모델, 비즈니스 로직은 테스트 게이트, 인증·결제·마이그레이션은 테스트+오너 승인 — 가장 위험한 20%만 강하게 게이트해도 효과 대부분을 얻는다. [가드레일]
11. 리뷰어 판정 자체도 오너가 주기적으로 표본 검사한다(자기선호 편향 감시). [학술][가드레일]

### C. 인간(마스터) 승인 지점
12. 인간 게이트는 딱 2곳에 고정: **작업 전 계획 승인(plan mode) + 배포 전 PR 승인** — 코드가 아니라 계획서·트리아지 요약·테스트 결과를 읽고 판정한다. [사례][가드레일]
13. **오너 전결 5종**: 결제·환불·가격 / 법률·규제(노동법·의료기관 직원 PII 포함) / 자격증명·권한 변경 / 비가역 행위(삭제·마이그레이션) / 고객 대상 발신 — 코드를 못 읽어도 누를 수 있는 승인들이라 비개발 오너에게 오히려 적합. [가드레일]
14. 에이전트에게 main 브랜치·프로덕션 DB 쓰기 권한을 상시 부여하지 않는다: 전용 브랜치 + draft PR + 브랜치 보호 — 프롬프트 지시("하지 마")는 가드레일이 아니고 권한이 가드레일이다(Replit 사건). [사례][가드레일]
15. 습관화 경계: AI PR 승인은 시간이 갈수록 형식화된다(+14.5%p) — 오너 승인도 위험 티어 높은 것에 집중해 러버스탬프화를 막는다. [가드레일]

### D. 비용 통제
16. 멀티에이전트는 토큰 ~15배 소모가 실측치 — **조사·설계에만 병렬을 켜고 단순 수정은 단일 세션**으로, 예산은 일 소프트캡/일 하드컷/월 실링 3단으로 먼저 세운다. [사례][가드레일]
17. 안정화된 반복 작업(청구·알림·정기 점검)은 LLM 판단에서 스크립트·cron·결정적 검증으로 강등한다 — 실행마다 성과 분산이 큰 것 자체가 사업 리스크다(Vending-Bench). [가드레일]
18. 저위험 단계(요약·문구·1차 트리아지)는 저가 모델로 다운티어한다. [가드레일]

### E. 수익화 전 준비
19. 결제 연동 전 필수 마일스톤: 자동 보안 스캔 정례화(`/security-review` 등) + 백업에서 실제 복구해보는 리허설 + 전 에이전트 행위 로깅. [가드레일]
20. 가격·환불·정책은 에이전트가 접근 못 하는 설정값으로 두어 고객·외부 텍스트의 설득(프롬프트 인젝션 포함)으로 양보가 발생하는 경로를 차단하고, "완전 자동 수익화"가 아닌 **오너가 승인 큐와 대시보드만 보는 준자동**을 현실적 목표로 잡는다. [가드레일][사례]

## 5. 검수 소견

**조사1 (학술)**: 커버리지·출처 품질 모두 우수 — 주요 논문의 학회·arXiv 번호가 구체적이고, "무엇이 증거이고 무엇이 연극인가"를 나눈 결론이 다른 두 보고서와 독립적으로 정합한다. 다만 arXiv:2512.08296(2025), arXiv:2511.07784 등 일부 최신 번호와 세부 수치(+80.8%/-70%)는 원문 재확인을 권하며, 벤치마크 점수는 장난감 과제 기준임을 본인도 인정하므로 수치보다 메커니즘만 채택했다.

**조사2 (실전 사례)**: 이번 사용자 맥락(비개발 솔로 오너)에 가장 밀착된 보고서로, Cora/Compound Engineering·Copilot 브랜치 보호 등 즉시 복사 가능한 관행이 많다. 다만 블로그·홍보성 2차 출처 비중이 높고, "90.2% 우위"는 Anthropic 자체 평가, "23세 월 $45K" 류의 솔로 파운더 성공담은 생존 편향이 큰 일화이므로 근거가 아닌 동기부여 수준으로 취급해야 한다.

**조사3 (가드레일)**: 실패 사례(Vend, Replit, TheAgentCompany)와 방어 규칙의 연결이 구체적이고, 사람 전결 5종·위험 티어링은 통합 목록의 뼈대가 됐다. 재검증 필요 항목 둘: (1) "Habituation at the Gate"의 arXiv 번호 2606.22721은 형식상 존재할 수 없는 번호라 실재 여부 확인 필요(다만 Intercom 실무 글이 같은 결론을 뒷받침), (2) 17.2배/4.4배 수치를 MAST에 귀속한 것은 학술 보고서 기준 Scaling 논문 소속으로 교정해야 한다. "일 $50/$100 예산선" 같은 수치는 특정 벤더 블로그 출처이므로 절대값이 아닌 예시로 받아들일 것.
