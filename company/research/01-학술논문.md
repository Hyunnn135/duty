# 조사1 (학술 논문) 보고서

# 학술 문헌 조사 보고서: LLM 에이전트를 "회사 조직"처럼 구성하는 것의 실효성

(다중 에이전트 LLM 조직 구조 — 무엇이 품질을 높이고, 무엇이 토큰 낭비인가)

## 1. 주요 소스별 정리

### A. "가상 소프트웨어 회사" 프레임워크 계열

**1. MetaGPT: Meta Programming for a Multi-Agent Collaborative Framework** — ICLR 2024 (Oral), arXiv:2308.00352
- 발견: PM/아키텍트/엔지니어/QA 등 역할을 나누되, 자유 대화가 아닌 **표준 운영 절차(SOP)와 구조화된 산출물**(요구사항 문서, 설계 다이어그램 등)로만 소통하게 했더니 HumanEval 85.9~89%, MBPP 87.7%로 당시 SOTA. 실행 피드백(코드를 실제로 돌려보는 것)만으로 MBPP +5.4%p.
- 적용점: 베낄 것은 "역할" 자체가 아니라 **구조화된 중간 산출물(문서)과 실행 검증**. 자유 채팅형 협업은 오히려 잡음.

**2. ChatDev: Communicative Agents for Software Development** — ACL 2024, arXiv:2307.07924
- 발견: 설계→코딩→테스트 단계별로 2인 대화(instructor/assistant) 체인. 앱 하나 평균 약 7분, $0.3 이하. 핵심 기여는 "communicative dehallucination"(리뷰어가 모호하면 되묻게 하는 프로토콜). 단, 생성물은 장난감 수준.
- 적용점: "되묻기(요구사항이 모호하면 질문 후 진행)" 프로토콜은 베낄 가치. 데모용 조직 구조를 그대로 이식하지 말 것.

**3. CAMEL** — NeurIPS 2023, arXiv:2303.17760
- 발견: 2-에이전트 롤플레잉 협력의 원조. 저자들 스스로 **역할 뒤바뀜(role flipping), 대화 이탈, 종료 실패** 등 자율 협력의 고질적 실패를 보고.
- 적용점: 역할 프롬프트만으로 알아서 협업하리라 기대하지 말 것 — 외부 구조(고정 턴 순서, 산출물 스키마)로 강제해야 함.

**4. AutoGen** — COLM 2024 / arXiv:2308.08155
- 발견: 범용 프레임워크. 코딩 과제에서는 대체로 **코더 + 실행기 2개 조합**이 효과의 대부분.
- 적용점: 프레임워크 도입 자체가 품질을 올리지 않음. 핵심은 "코드 실제 실행→피드백 루프".

### B. 계층 검증 / 매니저-워커 / 리뷰 계열

**5. MAGIS (GitHub Issue Resolution)** — NeurIPS 2024, arXiv:2403.17927
- 발견: Manager/Custodian/Developer/QA 4역할로 SWE-bench에서 GPT-4 단독 대비 해결률 8배(13.94%). 단, 이후 단일 에이전트+좋은 스캐폴딩이 크게 추월.
- 적용점: "이슈→파일 찾기→계획→구현→QA" 단계 분해는 유효. 역할 수 늘리기는 정당화 안 됨.

**6. AgentCoder** — arXiv:2312.13010
- 발견: 프로그래머 + **테스트 설계자(코드를 안 보고 테스트 작성)** + 테스트 실행자 3역할. HumanEval 96.3% + 토큰은 기존 다중에이전트의 절반 이하(56.9K vs 138.2K).
- 적용점: 가장 베낄 가치 높음. **구현과 분리된 컨텍스트에서 테스트를 독립 작성** — 간호사 스케줄링 제약을 테스트로 먼저 고정하는 방식과 정확히 맞음.

**7. Self-collaboration Code Generation** — TOSEM 2024, arXiv:2304.07590
- 발견: 분석가/코더/테스터 롤 프롬프트만으로 GPT-3.5가 단독 대비 향상. 향상분 대부분은 "요구사항 분해"와 "테스트 피드백".
- 적용점: 약한 모델일수록 역할 분리 이득이 큼. 최신 강력 모델에서는 이득 축소.

### C. "언제 다중 에이전트가 이기고 지는가"

**8. More Agents Is All You Need** — TMLR 2024, arXiv:2402.05120
- 발견: 같은 질문 N개 샘플링→다수결만으로 성능 상승. 어려운 과제일수록 이득.
- 적용점: "여러 초안 생성 후 선택"은 값싸고 검증됨. 단, 자동 채점(테스트) 가능한 과제에서만 안전.

**9. Are More LLM Calls All You Need?** — NeurIPS 2024, arXiv:2403.02419
- 발견: 호출 수 증가 시 성능 **비단조** — 오르다 떨어짐. 어려운 문제는 다수가 오답으로 수렴해 악화.
- 적용점: "에이전트 더 붙이면 좋아진다" 가정 폐기. 초과분은 토큰 낭비 + 품질 하락.

**10. Towards a Science of Scaling Agent Systems** — Google/DeepMind/MIT 2025, arXiv:2512.08296
- 발견: 180개 구성 통제 실험. 독립 병렬 다중 에이전트는 오류 **17.2배 증폭**, 중앙 조정자 있으면 4.4배로 감소. 분해 가능 과제 +80.8%, 순차 의존 과제 **-70%**. 단일 정확도 ~45% 초과 과제에선 에이전트 추가가 수익 체감/퇴행.
- 적용점: 가장 직접적 지침. 순차 의존 코드베이스에 병렬 에이전트 풀어놓으면 오류 증폭. 쓴다면 **중앙 조정 1명 + 독립 작업에만 분배**.

**11. Why Do Multi-Agent LLM Systems Fail? (MAST)** — NeurIPS 2025, arXiv:2503.13657
- 발견: 1,600+ 트레이스, 14개 실패 모드: **명세/설계 결함 ~42%, 에이전트 간 정렬 실패 ~37%, 검증·종료 실패 ~21%**. 실패 대부분은 모델 능력이 아니라 조직 설계 결함.
- 적용점: 에이전트 늘리기 전에 **명세부터**. "QA 에이전트가 봤으니 됐다"식 검증이 실패 원인 3위 — 검증은 실행/테스트 기반이어야.

**12. Agentless** — FSE 2025, arXiv:2407.01489
- 발견: 단순 2단계 파이프라인(위치 파악→수정, 다중 패치 생성 후 테스트 선별)이 모든 오픈소스 에이전트를 이김, 비용 $0.70.
- 적용점: **잘 설계된 단순 파이프라인 + 테스트 선별**이 에이전트 군단보다 나을 수 있음.

**13. LLMs Cannot Self-Correct Reasoning Yet** — ICLR 2024, arXiv:2310.01798 (+ arXiv:2511.07784)
- 발견: 외부 신호 없는 자기 수정은 무익/악화. 같은 모델끼리 토론은 다수결과 등가 — **에코 챔버**.
- 적용점: "리뷰어가 말로 지적→수정" 루프는 테스트 실패 로그 등 외부 근거 없으면 대체로 무의미.

### D. LLM-as-Judge 신뢰성

**14. Judging the Judges (Position Bias)** — arXiv:2406.07791
- 발견: 제시 순서에 따라 판정이 뒤집히는 위치 편향 유의미.
- 적용점: 비교 판정은 순서 바꿔 2회 질의하거나 테스트 통과율로 판정.

**15. Self-Preference Bias in LLM-as-a-Judge** — arXiv:2410.21819
- 발견: 자기(같은 계열 모델) 출력을 체계적으로 과대평가.
- 적용점: Claude가 Claude 코드를 리뷰하면 구조적으로 후함. 리뷰 "승인"은 참고 의견.

### E. 서베이

**16. LLM-Based MAS for SE: Literature Review** — ACM TOSEM 2025 등
- 발견: 문헌 다수가 장난감 벤치마크 중심. 실제 레포 수준에서 다중 에이전트 우위 근거 빈약.
**17. MacNet (Scaling MAS)** — ICLR 2025, arXiv:2406.07155
- 발견: 1,000+ 에이전트에서 성능은 포화 곡선. 위상이 인원수보다 중요. "감독 비평가→실행자" 단방향 유리.

## 2. 종합: 증거 기반 vs 연극

- [증거] 실행 기반 검증 루프(테스트 실행 피드백)가 진짜 엔진
- [증거] 구현과 분리된 테스트 작성(AgentCoder)
- [증거] 구조화된 산출물 + 단계 게이트(자유 대화 금지), 명세 개선이 에이전트 추가보다 우선
- [증거] 중앙 조정자 1 + 독립 하위 작업에만 병렬화 (순차 의존 작업은 단일이 낫다)
- [연극] 직함 많은 가상 회사 조직도 (역할 수 증가 자체는 근거 없음, 최신 모델일수록 이득 소멸)
- [연극] 외부 근거 없는 리뷰/토론 (에코 챔버)
- [연극에 가까움] LLM 심판 단독 승인 게이트 (위치·자기선호 편향) — 테스트 통과로 대체
- [조건부] 다중 초안 생성 후 테스트 선별 (자동 채점 가능할 때만, 호출 수 비단조)
- 실천 요약: ① 오너는 명세·수용 기준 공급자, ② 오케스트레이터 1 + 얇은 구조, ③ 게이트는 CI 테스트, ④ 테스트 작성자만 컨텍스트 분리, ⑤ 에이전트 추가는 측정 후에만
