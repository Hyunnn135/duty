# 교훈 대장 (Lessons Ledger)

> 기록 규정: company/regulations/07-교훈기록.md
> 모든 부서는 작업 착수 전 관련 재발 방지 규칙을 확인한다.

## L-1 실명 데이터가 저장소에 커밋됨 (2026-08-19)
- 무슨 일: 실측 근무 데이터·기본 명단에 간호사 실명 25명·사번 25건이 커밋되어
  있었고, git 이력에도 남아 있었다.
- 원인: 초기 개발 때 "동작 우선"으로 실데이터를 그대로 사용, 개인정보 관점의
  점검 단계가 없었다.
- 조치: 전 파일 가명화 + git 이력 전체 재작성(강제 푸시). GitHub 서버 캐시
  삭제는 Support 요청 대기.
- 재발 방지 규칙: **개인정보(실명·사번·연락처)는 어떤 파일에도 커밋하지 않는다.
  테스트·예시 데이터는 처음부터 가명으로 만든다.**

## L-2 나이트 불가 프리셉티가 운영 모드 생성을 통째로 막음 (2026-08-19)
- 무슨 일: 교육 중 신규가 나이트 불가일 때, 미러링 제약이 교육자의 나이트까지
  원천 봉쇄해 전체 근무표 생성이 INFEASIBLE이 되는 버그.
- 원인: 제약 간 상호작용(미러링 × 나이트 하드 밴드)을 단독 제약 테스트만으로
  검증하고, 조합 시나리오 테스트가 없었다.
- 조치: 미러링에서 N·O 제외, 조합 회귀 테스트 추가.
- 재발 방지 규칙: **하드 제약을 추가·수정하면 기존 하드 제약과의 조합 시나리오
  테스트를 최소 1개 함께 추가한다.**

## L-3 검수 없는 대량 변경에서 26건의 결함이 리뷰로 발견됨 (2026-08-19)
- 무슨 일: 사번 전환·부서원 화면·모바일 작업에서 3관점 교차 검수 2회가
  단독 작업이 놓친 결함 26건(마이그레이션 경쟁, 사번 대소문자 정보 노출,
  390px 화면 깨짐 등)을 잡았다.
- 원인: 단독 작업자는 자기 가정 안에서만 검증하게 됨.
- 조치: 검수부 상비화(T3 필수), 검수 관점 분리 규정화.
- 재발 방지 규칙: **T3(인증·개인정보·데이터·돈) 변경은 반드시 2관점 이상의
  독립 검수를 거친다.**

## L-4 마감 시각의 시간대 해석 오류 (2026-08-19)
- 무슨 일: 신청 마감을 UTC로 해석해 공지된 마감보다 9시간 늦게 닫혔다.
- 원인: 사용자(한국)와 서버(UTC)의 시간대 차이를 고려하지 않은 기본값.
- 조치: 시간대 없는 입력은 KST로 해석 + 회귀 테스트.
- 재발 방지 규칙: **날짜·시각을 다루는 모든 기능은 "사용자는 KST"를 명시적으로
  처리하고 경계 테스트를 붙인다.**

## L-5 문서와 실제 동작의 불일치 (2026-08-19)
- 무슨 일: 사용 설명서·화면 문구가 이미 완화된 규칙("같은 팀 오프 겹침 불가")을
  하드 규칙처럼 안내하고 있었다.
- 원인: 규칙 변경 시 문서·문구 갱신이 파이프라인에 없었다.
- 조치: 문구 3곳 수정. 문서-현실 불일치를 검수 점검 항목에 포함.
- 재발 방지 규칙: **동작 규칙을 바꾸면 같은 작업 안에서 사용자 문구·설명서를
  함께 갱신한다.**
